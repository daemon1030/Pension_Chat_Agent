현재 구현

RAG CLI 서비스

질문 범위를 검사하고, CLOVA 임베딩으로 로컬 JSONL을 검색한 뒤, 검색 근거만 전달해 구조화 답변을 생성합니다.

  • 키워드 검색과 벡터 검색
  • LangGraph 3단계 흐름
  • CLOVA API Adapter
  • Pydantic JSON 검증·재요청
부분 구현

문서 전처리 파이프라인

PDF·DOCX·XLSX·PPTX 변환과 의미 검토 스크립트가 있으나, 현재 작업공간에는 README가 설명하는 중간 산출물 대부분이 없습니다.

  • 전처리 로직은 scripts/preprocessing/
  • 실제 데이터는 raw/doc1.pdf, processed/doc1.json
목표 구조

운영 상담 시스템

AGENTS.md에 제시된 최종 방향입니다. 현재 코드리뷰에서 이미 구현됐다고 전제하면 안 됩니다.

  • FastAPI POST /chat
  • PostgreSQL + pgvector
  • 정형 Fact DB + Rule Engine
  • Guardrails + 세션 상태 복원
리뷰 기준점
README는 의도와 사용법을 설명하지만, 현재 체크아웃의 사실은 파일 시스템과 import 경로가 우선합니다. 특히 data/**와 config/**는 Git에서 제외됩니다.

추천 코드 리뷰 순서

1

계약부터 본다

src/graph/state.py와 src/llm/schemas.py에서 입력·출력 상태와 불변식을 파악합니다.

2

실행 경로를 따라간다

scripts/rag/chat.py → workflow.py → nodes.py 순서로 실제 호출 관계를 확인합니다.

3

4

5

전처리의 원문 보존을 본다

Parser → enrich → semantic review → final knowledge가 출처를 잃지 않는지 샘플 하나로 역추적합니다.

6

테스트와 문서의 약속을 대조한다

테스트가 구현을 보호하는지, README가 실제 체크아웃 상태를 과장하지 않는지 확인합니다.

우선순위별 리뷰 포인트

P0
재현 가능한 개발 환경이 없다

의존성 manifest가 없고 현재 가상환경에는 langgraph가 없습니다. CI와 신규 개발자 환경에서 테스트가 시작되지 않습니다.

P0
문서·데이터 상태가 드리프트했다

README의 데이터 디렉터리 설명과 실제 체크아웃이 다릅니다. 데이터가 Git 제외이므로 “필수 입력/생성물/선택 산출물” 계약이 필요합니다.

P1
벡터 검색에 최소 관련도 기준이 없다

임베딩 검색은 Top-K를 항상 반환합니다. 관련 없는 연금 질문에도 가장 가까운 문서를 근거로 답할 위험이 있습니다.

P1
보안 흐름이 목표보다 얇다

현재 Input Guard는 연금 용어 포함 여부뿐입니다. Prompt injection, 데이터 탈취, 입력 길이 제한, Output Guard는 미구현입니다.

P1
임베딩 갱신이 내용 변경을 감지하지 않는다

chunk_id 완료 여부만 확인하므로 같은 ID의 본문 변경이나 삭제가 기존 JSONL에 남을 수 있습니다.

P2
패키지 초기화가 단위 테스트 격리를 약화한다

src/graph/__init__.py가 workflow를 eager import하여 단순 노드 import에도 LangGraph가 필요합니다.

P2
플랫폼 의존 OCR 경로

Tesseract 경로가 macOS Homebrew 위치로 고정되어 현재 Windows 환경 및 CI에서 재사용하기 어렵습니다.
